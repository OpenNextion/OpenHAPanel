# 设备 i18n 组件

设备翻译集中维护在 `locales/`。目前提供英文 `en` 和德语 `de`，默认英文。字体按完整字体处理，本组件不检查、不生成、不修改字体。`web-ui/` 不属于本次改动范围。

任务进度、用户约束及恢复入口见 [实施工作流](../../docs/i18n-workflow.md)。

## 维护翻译

- `locales/en.json`：基准 key 和英文文本。
- `locales/de.json`：德语翻译。
- `locales/manifest.json`：语言代码、自称名称、文件和复数规则。
- `tools/generate_i18n.py`：校验并生成 C 常量表和 `i18n_keys.h`。

新增文案时先向英文添加稳定的语义 key，例如 `common.cancel`，再补充各语言的对应翻译。代码使用生成的 `I18N_COMMON_CANCEL`；不要用英文句子作 key，不要在页面中判断语言。

缺失某条译文时回退英文。缺失 key、空译文、重复 key、未知 key、占位符不一致等情况会由生成器检查。省略 key 表示允许英文回退；空字符串不是回退标记。

只校验资源，不编译：

```sh
python3 components/i18n/tools/generate_i18n.py
PYTHONDONTWRITEBYTECODE=1 python3 components/i18n/tools/test_generate_i18n.py
```

用户自行编译时，CMake 在实际 configure 阶段生成资源到组件的构建目录；依赖扫描阶段不执行生成。JSON 和生成脚本修改会触发重新配置。首次加入此组件及新的 main 源文件后，用户应先执行 `idf.py reconfigure`，再按原流程编译。此任务未运行这些命令。

## 增加语言

1. 在 `locales/` 增加 UTF-8 JSON 文件；建议复制英文 key 后翻译。
2. 在 `manifest.json` 的 `languages` 登记 `code`、`name`、`file` 和 `plural_rule`。英文保持第一项和默认项。
3. 检查参数、日期语序及时间表达。当前支持 `one_other`（数字 1 使用 one）和 `other`（全部使用 other）两种复数规则。
4. 执行资源校验，再由维护者编译和设备验证。

新增语言的标准字符串和日期模板无需改页面。需要其他复数类别的语言，应先扩展组件的规则及对应资源；文字方向及复杂文字排版不在本次实现范围。资源随固件发布，不支持运行时上传语言包。

## 语言配置与兜底

继续使用 `device_info.json` 的 `language` 字段和现有 `Device.SetLanguage` 接口（具体协议方法以 `WEB_API_METHOD_SET_LANGUAGE` 为准）。接口 `data` 示例：

```json
{"language": "de"}
```

规范化规则：不区分大小写的完整匹配，其次匹配基础语言，最后回退 `en`。例如 `de-DE`、`de_AT` 使用 `de`，`zh`、`fr`、空值使用 `en`。设备保存规范化后的代码，通知中也返回规范化值。JSON 参数类型错误仍沿用原接口错误处理。

语言字段扩大到 32 字节。加载旧配置和保存配置均经过同一规范化规则，不另设 NVS 语言值。只有配置保存成功后才更改运行中的语言；启动从已有配置恢复。

Web 项目代码、语言选项和资源没有改动，所以本次不会在现有 Web 设置页新增德语选项。可以使用现有语言设置协议指定 `de`。

## 使用接口

```c
const char *text = i18n_get(I18N_COMMON_CANCEL);
```

返回值是固件生命周期内有效的只读文本，不需要释放。找不到某语言译文时自动返回英文；`i18n_find("common.cancel")` 可按 key 查询，未知 key 返回 NULL。

固定文本标签使用设备展示适配器：

```c
ui_i18n_label_set_text(label, i18n_get(I18N_COMMON_CANCEL));
```

适配器只识别词库返回的指针，保存 key，并在标签删除时解除绑定。普通用户字符串不会按内容猜测为翻译 key。生成器为每个消息生成独立字符数组，因此英文相同、语义不同的 key 也可以正确切换。

经过 `snprintf` 或其他复制产生的动态文本不再带 key，需要所属组件在语言变化时重新格式化。

## 参数和日期

日期和相对时间使用命名参数，翻译可调整顺序：

```json
{"date.full": "{day}. {month} {year}"}
```

`i18n_format()` 接收名字和值的数组，检查缺少的参数、缓冲区容量，并保持 UTF-8 截断边界。返回 false 表示未完整输出。`i18n_copy()` 用于复制普通译文，不将译文解释为 printf 格式。

为接入已有 UI 格式化代码，部分设备提示保留 printf 格式。各语言必须使用与英文完全相同的格式符和参数顺序。生成器拒绝 `%n`、动态宽度、位置参数及参数不匹配。新文案需要调整参数顺序时应使用命名模板；不要直接将用户文本作为格式串。

相对时间按单位、过去/将来/时长、复数类别选择完整句子。例如德语的 `vor {count} Tagen` 与 `{count} Tage` 分开维护，不能简单拼接后缀。时间戳解析和时区计算继续使用原逻辑。数值测量、温度单位和协议数字格式保持原有行为。

## 界面更新和协议边界

- 语言选择是原子状态；i18n 核心不依赖 LVGL 或配置存储。
- 屏幕的 200 ms LVGL 定时器通过版本计数检测语言变化（快速切换后回到原语言也会刷新），并在 LVGL 执行上下文中刷新。
- 静态标签原地更新；卡片和徽标从 HA 缓存重新生成状态。
- 详情页在加载完成、触摸释放后重建内容，保留所选实体及返回页面；展开的选择菜单会关闭，详情内容的滚动位置可能重置。
- 配网页刷新其视图，通知重新格式化。密码恢复和 OTA 保留原有计时器和业务状态；倒计时文本在原有下一次秒级 tick 更新。
- `entity_state_translation` 统一二元传感器语义及标准状态。空调选项只翻译显示值，回调仍携带原始选项。
- 用户命名、HA 自定义选项、协议状态、服务参数、日志、地址和版本号保持原值。字体文件不作处理。
